# TAZMA: браузерний відеоредактор і ядро експорту відео на WebCodecs

TAZMA – це браузерний відеоредактор, створений для дослідження експорту відео на основі **WebCodecs**. Назва походить від слова «тасма»: кліпи на таймлайні вишиковуються в таку стрічку.

Головне в проєкті – не інтерфейс, а **ядро експорту**: модуль, який приймає проєкт (список кліпів та ефектів) і повертає готовий файл. Редактор потрібен як середовище, де метод працює на реальному монтажі і де його можна виміряти.

> **Статус:** етап 4 з 8 – звичайний експорт (у роботі). Далі – вибірковий експорт.

---

## Мета

Тема кваліфікаційної роботи: «Розробка методу перекодування відео на базі відеоредактора з WebCodecs».

Проєкт створено в навчальних та дослідницьких цілях у межах виконання магістерської кваліфікаційної роботи.

## Ключові ідеї

Метод експорту складається з трьох частин, які плануються до реалізації та експериментальної перевірки:

* **Планування (вибіркове перекодування).** Не перераховувати те, що не змінювалося: незмінені фрагменти копіюються без розпакування, перераховуються лише ефекти та стики.
* **Виконання (конвеєр зі зворотним тиском).** Кадри проходять через декодер, ефекти й кодувальник так, щоб не переповнювалася пам'ять і не простоювали кодеки.
* **Надійність (відновлюваний експорт).** Контрольні точки у сховищі браузера, щоб закрита вкладка або збій не коштували всього експорту.

Кожен метод порівнюється зі звичайним повним перекодуванням на одному й тому самому наборі відео за часом експорту, піковою пам'яттю, часткою перерахованих кадрів, якістю та надійністю.

## Склад системи

```text
Редактор-демо ──► Ядро експорту ──► Готовий файл
                  ├─ Планувальник
                  ├─ Конвеєр
                  └─ Контрольні точки

Стенд замірів ──► запускає ядро, збирає час, пам'ять і якість
```

* **Ядро експорту** – самостійний модуль без інтерфейсу. Тут живуть три методи; це основний результат роботи.
* **Редактор-демо** – мінімальний інтерфейс: файли, перегляд, таймлайн, текст і один ефект, кнопка експорту.
* **Стенд замірів** – сторінка, яка запускає експорт на наборі відео в різних режимах і збирає дані для роботи.

## Заплановані можливості

* Відкриття відео, перегляд, читання параметрів та ключових кадрів.
* Таймлайн з однією відеодоріжкою та звуком: нарізка, видалення, перестановка кліпів.
* Текст поверх відео та один простий ефект.
* Експорт у MP4 (H.264, VP9, AV1) та WebM (VP9, AV1); перелік залежить від браузера.
* Вибірковий експорт зі статистикою «скопійовано / перераховано».
* Експорт у фоні з обмеженням кількості кадрів у пам'яті.
* Відновлення експорту після закриття вкладки.

## Вимоги до браузера

* Браузер на основі Chromium (Chrome, Edge) із підтримкою WebCodecs та OPFS.
* Кодування H.264 залежить від браузера, платформи та апаратного прискорення; WebM (VP9) використовується як запасний формат.
* Основні заміри виконуються в Chrome; Firefox і Safari перевіряються за можливості.

## Запуск

Потрібен Node.js 20.19+ або 22.12+. Сервер не потрібен: застосунок повністю працює в браузері.

```bash
npm install
npm run dev
```

Після запуску застосунок буде доступний за адресою:

```text
http://localhost:5173
```

Перевірка зібраної версії (так само, як на хостингу; заміри для роботи виконуються саме на ній):

```bash
npm run build
npm run preview
```

## Керування

* Кілька файлів можна перетягнути одразу або додати кнопкою «Додати файли». Кнопка «+» біля файлу додає ще один кліп із нього в кінець таймлайну.
* Клік або перетягування по таймлайну переміщує курсор; клік по кліпу виділяє його.
* **S** – розрізати кліп у місці курсора, **Delete** – видалити виділений кліп, **Пробіл** – відтворення й пауза.
* Кнопки «←» і «→» міняють виділений кліп місцями із сусіднім; «−», «+» і «Вписати» змінюють масштаб.
* **T** (або кнопка «Текст») додає напис у місці курсора на окрему доріжку під відео. У панелі справа задаються текст, початок і кінець (кнопки «= курсор»), положення, розмір і колір.
* Для виділеного кліпа в панелі справа вмикається ефект «Чорно-білий» із регульованою силою.
* Під таймлайном заштриховано ділянки, які при експорті доведеться перерахувати (кліпи з ефектом і час під написами), і показано їхню частку. Решту можна копіювати без перерахунку; саме з цього почнеться планувальник вибіркового експорту.

* Кнопка «Експорт» угорі відкриває діалог: контейнер, відео- й аудіокодек, якість і розмір кадру (лише зменшення). У списках лише те, що цей браузер уміє кодувати. Під час експорту видно прогрес, швидкість і залишок часу, його можна скасувати. Готовий файл можна переглянути й зберегти; під ним показано розмір, час кодування та швидкість.

Відтворення результату йде через один елемент `<video>`, який перемикається між кліпами. Це лише попередній перегляд; готове відео збирає ядро експорту (етапи 4–6).

Написи прив'язані до часу, а не до кліпів: перестановка й розрізання кліпів їх не рухають, а якщо ролик скорочується, напис за кінцем обрізається або зникає. Кадр проєкту береться за першим кліпом, інші файли вписуються в нього.

Експорт на цьому етапі – **звичайне повне перекодування**, точка відліку для порівняння з наступними методами: кожен кадр проєкту декодується, проходить через ефект і напис та кодується заново.

Один і той самий код малює напис у перегляді й малюватиме його при експорті (`src/render/overlay.ts`), а ефект описується одним рядком фільтра (`src/project/effects.ts`), який підходить і для CSS, і для canvas. Тому у файлі буде те, що було видно в перегляді.

## Структура коду

```text
src/
├── media/        читання файлів (контейнер, кодеки, ключові кадри); без інтерфейсу
├── project/      модель проєкту, чиста логіка таймлайну, написів, ефектів і «зон перерахунку», відтворення, імпорт
├── render/       малювання написів на кадрі (спільне для перегляду й експорту)
├── export/       ядро експорту: план, кадри, звук, кодеки, налаштування; без інтерфейсу
├── components/   компоненти інтерфейсу
├── App.tsx
├── main.tsx
└── styles.css
tests/            автоматичні тести логіки (таймлайн, написи, ефекти, перерахунок, малювання, частини експорту)
```

## Як працює експорт

1. `plan.ts` розкладає кліпи на сегменти з їхнім зсувом на таймлайні.
2. Для кожного кліпа Mediabunny віддає кадри по порядку; `compose.ts` малює кадр на `OffscreenCanvas`: чорне тло, фільтр ефекту, кадр із вписуванням (`contain`), потім написи тим самим кодом, що й перегляд.
3. Звук нарізається за вікном кліпа й зсувається на таймлайн; для кліпів без звуку вставляється тиша. Усі блоки приводяться до стерео 48 кГц до кодувальника (`audioFormat.ts`).
4. `merge.ts` зливає відео- й аудіопотоки за часом, щоб муксер не накопичував одну доріжку наперед.
5. Результат збирається в пам'яті (`BufferTarget`) і віддається як `Blob`.

Розмір кадру береться за першим кліпом (парні сторони), решта вписується в нього. Кодування запускає `exportProject` у `src/export/exportProject.ts`.

Обмеження цього етапу: весь файл лежить у пам'яті до кінця експорту, а малювання кадрів іде в основному потоці. Потокове записування та відновлення (етапи 6–7) це змінять. H.264 і AAC кодуються, лише якщо їх підтримує браузер.
